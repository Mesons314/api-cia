# Direct Source Code Parsing (Zero-Contract API Analysis)

Yes, **this is 100% possible**. You can completely bypass the step of generating or uploading an OpenAPI contract by parsing the raw controller source files directly using **JavaParser**.

Here is the exact architecture and parsing logic to achieve this.

---

## 1. How It Works (Conceptual Data Model)

Instead of comparing two OpenAPI files, your scanner parses the controller files at two different git references (e.g., `HEAD` vs `HEAD~1`) and translates them into an in-memory collection of **Endpoint Signatures**.

```mermaid
graph TD
    subgraph Git State HEAD (New Code)
        NewFile[UserController.java] -->|JavaParser| NewSig[New Endpoint Signatures]
    end

    subgraph Git State HEAD~1 (Old Code)
        OldFile[UserController.java] -->|JavaParser| OldSig[Old Endpoint Signatures]
    end

    NewSig & OldSig -->|Compare Collections| Diff[Delta Engine]
    Diff -->|Output| Violations[Violations: Path Changed / Parameter Added]
```

---

## 2. Step-by-Step Implementation of the Parser

You will write a service class (e.g., `SourceCodeSpecScanner.java`) that does the following:

### Step A: Locate Controllers
Find all files ending with `Controller.java` or containing the `@RestController` annotation in the target codebase directory.

### Step B: Extract Endpoints Using JavaParser
For each controller class, extract:
1. **Base Path**: Read the class-level `@RequestMapping` annotation value (e.g., `/api`).
2. **HTTP Verb and Route**:
   - Scan methods for mapping annotations: `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`.
   - Read the path value (e.g., `/userData` or `/userdata`).
   - Combine Base Path + Method Path (e.g., `/api/userData`).
3. **Parameters**:
   - Inspect the method parameters.
   - Look for `@RequestParam` (query parameters), `@PathVariable` (path parameters), or `@RequestBody` (payload).
   - Record their types (e.g., `String`, `Integer`) and whether they are required.

---

## 3. The AST Diffing Logic

Once you have parsed the old and new versions of the class, you run a list-comparison algorithm:

```java
// Conceptual mapping structures generated by your parser
class EndpointSignature {
    String httpMethod;    // "GET"
    String path;          // "/api/userData"
    List<ParameterInfo> parameters;
}
```

### The Comparison Algorithm:
1. **Detect Path Removal**:
   - If an `EndpointSignature` exists in the **Old List** but its path + method combination does NOT exist in the **New List**, mark it as **REMOVED**.
   - Example: `GET /api/userData` is missing.
2. **Detect Path Addition**:
   - If it exists in the **New List** but not the **Old List**, mark it as **ADDED**.
   - Example: `GET /api/userdata` is present.
3. **Detect Renames (Heuristics)**:
   - If a path is removed and a new path is added in the same controller class with the exact same return type and method signature, mark it as **RENAMED**: `Path renamed from /userData to /userdata`.
4. **Detect Parameter Modifications**:
   - If path + method matches, compare the parameters:
     - If a parameter exists in the New list but not the Old list, mark it as **PARAMETER_ADDED**.
     - If a parameter's type changed, mark it as **PARAMETER_TYPE_MUTATED**.

---

## 4. Hooking it to Git

To automate this on commit:
1. Write a script that runs on `pre-commit` or `pre-push`.
2. The script finds the list of changed files using Git:
   ```bash
   git diff --name-only HEAD~1 HEAD | grep Controller.java
   ```
3. For every changed controller:
   - Read the file content at `HEAD` (current state) and `HEAD~1` (previous commit).
     - To get the previous version: `git show HEAD~1:src/main/java/.../UserController.java`.
   - Pass both contents to your backend:
     `POST /api/specs/compare-source` with inputs `currentSource` and `previousSource`.
4. Your backend runs the comparison algorithm and outputs the report instantly.
